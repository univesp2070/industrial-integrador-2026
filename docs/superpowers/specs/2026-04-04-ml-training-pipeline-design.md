## Objetivo

Implementar `firmware/models/train_model.py` — script Python que:

1. Gera dataset sintético (replicando a lógica do `SyntheticSensorEngine`) e/ou lê dados reais do PostgreSQL
2. Treina um modelo Keras supervisionado com saída de `anomaly_score` contínuo (0.0–1.0)
3. Exporta para TFLite (`.tflite`)
4. Gera automaticamente `firmware/lib/inference/model_data.h` como array C

Critério de aceite: `python firmware/models/train_model.py --synthetic` completa sem erro e atualiza `model_data.h` com bytes válidos.

## Dataset

### Modo sintético (`--synthetic`)

Replica a lógica do `SyntheticSensorEngine`:

```
Normal (80%):
  temperature: 27.0 ± 2.5 * sin(step/10) ± U(-0.3, 0.3)   [°C]
  vibration:   0.35 ± 0.08 * sin(step/10) ± U(-0.02, 0.02) [mm/s]
  current:     2.7  ± 0.25 * sin(step/10) ± U(-0.05, 0.05) [A]

Anomalia (20%):
  temperature += U(9.0, 16.0)
  vibration   += U(0.35, 0.75)
  current     += U(0.8, 1.4)

anomaly_score = min(1.0, mean([
    max(0, (temp - 34.0) / 14.0),
    max(0, (vib  - 0.55) / 0.45),
    max(0, (curr - 3.3)  / 1.2),
]) + 0.35 se anomalia injetada)

label binário para loss: 1 se anomaly_score >= 0.65, 0 caso contrário
```

Default: `--samples 10000`

### Modo banco (`--from-db`)

Query no PostgreSQL/TimescaleDB:

```sql
SELECT
    MAX(CASE WHEN sensor_type = 'temperature' THEN value END) AS temperature,
    MAX(CASE WHEN sensor_type = 'vibration'   THEN value END) AS vibration,
    MAX(CASE WHEN sensor_type = 'current'     THEN value END) AS current,
    MAX(CASE WHEN sensor_type = 'temperature' THEN anomaly_score END) AS anomaly_score
FROM sensor_data
WHERE device_id = %(device_id)s
  AND time > NOW() - INTERVAL '7 days'
GROUP BY date_trunc('second', time), device_id
HAVING COUNT(DISTINCT sensor_type) = 3
ORDER BY 1
```

Parâmetros: `--db-url postgresql://user:pass@localhost/edgeai`, `--device-id esp32-001`

### Modo combinado (`--synthetic --from-db`)

Concatena os dois datasets. Dados reais têm prioridade (listados por último no array, mesma distribuição de peso).

## Modelo

### Arquitetura Keras

```
Input(3)  →  Dense(8, relu)  →  Dense(4, relu)  →  Dense(1, sigmoid)
```

- ~140 parâmetros → ~560 bytes em TFLite float32, ~200 bytes com INT8
- Loss: `binary_crossentropy`
- Optimizer: `adam`
- Métricas: `accuracy`, `AUC`

### Normalização (pré-processamento)

Aplicada antes do modelo (não como camada Keras — compatibilidade TFLite Micro):

```python
X[:, 0] /= 100.0   # temperature  → [0, 1] (range 0–100°C)
X[:, 1] /= 2.0     # vibration    → [0, 1] (range 0–2 mm/s)
X[:, 2] /= 10.0    # current      → [0, 1] (range 0–10 A)
```

Mesma normalização usada em `inference_engine.cpp` modo `USE_TFLITE`.

### Split

80% treino / 20% validação. `random_state=42` para reprodutibilidade.

converter = tf.lite.TFLiteConverter.from_keras_model(model)
